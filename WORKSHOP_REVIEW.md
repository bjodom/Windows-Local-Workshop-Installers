**Historical review:** This evaluation tested the E4B package. The package was subsequently changed to Gemma 4 26B-A4B Q4_0; the timings and inference/skill validation below do not validate the new model.

Review date: 8 September 2026. Scope: RUN_EASY_SETUP.cmd, installer, payload binaries/manifests/checksums, start/stop scripts, participant documents, and relevant source at Hermes commit 30b83ab7b1f194503de9f5545d88c81c4db91e3f.

**Assessment: the core design works, but the package needs reliability corrections before a room-wide workshop.** A successful installation on one laptop is credible; it does not exercise rerun recovery, clean-machine dependencies, constrained networks, different memory configurations, or all skill behaviors.

This is an evaluation, not a patch to the distribution. The original installer, payload, exercises, and checksum manifests were not changed. Review scripts and evidence were added separately. No fresh installation, driver changes, full model download, reboot test, or fleet-wide validation was performed.

**Priority 1 — correct before distributing**

1. **Rerunning setup while the server is running can fail.** Install-HermesLocalWorkshop.ps1:296–298 recursively copies every payload item, including llama-server.exe, before Start-HermesLocalWorkshop.ps1 gets a chance to reuse the healthy endpoint. Windows locks running executables against replacement. A disposable-process test reproduced that file-lock failure without touching the installed server. This affects the ordinary “run the same setup again” recovery advice, including a failure after the server has started. Skip identical runtime files; for an actual runtime replacement, stop only the verified workshop process before replacing its files, then restart it. Do not use the full installer as the normal restart command.

2. **The meme exercise has a Windows rendering defect.** In the pinned optional skill's scripts/generate_meme.py, find_font() searches Linux/macOS font paths and a DejaVu name, but no Windows font paths. Its final ImageFont.load_default() call does not pass the requested size. A PNG can be created successfully with very small captions. Add a tested Windows font selection, such as an available Impact or Arial Bold under the Windows fonts directory, and a size-aware fallback. Check the actual long workshop captions visually. Since the skill lives in the installed Hermes repository, editing TASKS.md alone will not repair this code; distribute/apply a clearly identified workshop fix or choose a different exercised skill.

3. **Model download recovery can get stuck on a corrupt partial file.** The curl command always resumes .partial. A checksum failure preserves it; rerunning resumes from those same bytes, which cannot repair already corrupt data. -ForceModelDownload invalidates the final file but never resets .partial. Also, the fixed 7 GB free-space requirement rejects a nearly completed download even when enough space remains for the missing bytes. Provide a genuine restart-download path, quarantine a checksum-failed partial, calculate remaining download space, and bound network connection/stall time. Pin the Hugging Face revision instead of resolving main while expecting a fixed checksum. The checksum correctly prevents using unexpected bytes; it cannot keep a moving URL available forever.

4. **WORKSHOP READY is stronger than the verification.** The installer checks llama.cpp chat and Hermes version/config values, but not Hermes terminal execution, Git Bash behavior, skill discovery or file creation. -DoNotStartServer even writes WORKSHOP READY after skipping server/API tests. A previous ready marker is not invalidated at the beginning of a subsequently failed run. Add an actual short Hermes tool-and-file smoke test, verify all required skills/dependencies, and use distinct installed/unverified versus verified-ready states. Include a timestamp and remove or replace stale readiness state on failure. Our isolated successful task proves this laptop can do it, not that the distributed installer checks it for participants.

**Priority 2 — control the laptop/network differences**

5. **The GPU check does not guarantee the selected device or enough memory.** Setup verifies that an Intel Vulkan device exists, but startup does not pass --device. On a machine with multiple eligible GPUs, it does not explicitly constrain inference to the intended Intel iGPU. Startup fixes context at 65,536 and GPU layers at all, with no RAM/memory-budget gate or workshop tuning options. The model alone is approximately 5.14 GB; KV cache, compute buffers, Windows, Hermes and other applications add to memory pressure. Record the tested PTL SKU, driver, RAM and server allocation logs; explicitly select the detected Intel device. Validate any smaller-context preset against the actual Hermes prompt/tool load before adopting it. Do not assume that a 16 GB participant laptop is equivalent to this 32 GB-class machine.

6. **Internet requirements are understated.** The pinned upstream installer bootstraps uv, Python, Git, Node and Python/Node dependencies, reaching more than the two domains named in README.md. Examples include astral.sh, nodejs.org, PyPI/package-file hosts, npm and GitHub release-asset hosts. It first attempts a locked Python install but can fall back to fresh PyPI resolution; uv and some bootstrapped components are not frozen by the Hermes commit. A pin therefore reduces drift without making this a fully offline/reproducible installer. Git Bash also has to execute under the organization's endpoint policy. Test a standard-user machine on the actual event network. Preinstall before the event and retain a verified model/cache recovery option. Twenty attendees downloading the model alone transfer approximately 103 GB, before other dependencies.

7. **7 GB is not a whole-install disk requirement.** The disk check happens after payload copy and Hermes installation. It does not reserve space for Python, repository, packages, extraction/cache data, or preserved invalid models/repository backups. Check space early on both the installation and temporary/cache drives. Measure a clean installation's peak footprint and choose a buffer from that measurement; the current documented minimum has not been validated as an end-to-end requirement.

8. **Custom Hermes homes and existing profiles are inconsistent with hardcoded paths.** The upstream installer honors process HERMES_HOME, but this wrapper searches for the launcher/Git and backs up config beneath LOCALAPPDATA\hermes. An existing custom home can therefore install in one place and be validated/backed up in another, or lead the wrapper to use an old default installation. Exercise 3 reads the User registry variable rather than the process's active home, and may miss an active profile. Resolve one active home consistently, or use a dedicated workshop home and matching launcher. Existing terminal/provider/fallback settings also need an explicit workshop baseline. --SkipHermesInstall only checks --version output, not the required commit.

9. **Startup recovery needs clearer state management.** A startup timeout leaves the newly launched server running. An immediate retry may see its occupied port and tell the attendee to close an application. Health plus alias matching can also reuse another server advertising the same alias without establishing this package's executable/model/GPU provenance. Track the verified owned process and distinguish loading from conflict. The public -Port option is incomplete for the overall workshop: installer API tests, Hermes configuration and all exercises still hardcode 8080.

**Exercise and participant-document corrections**

- The progression from bundled to installed to custom skills is useful. Retain explicit skill invocation and tangible output files. For PMs/AEs, explain that a skill is a reusable procedure, the model selects/actions it through tools, and outputs must be checked against evidence.
- Exercise 1: permit the required read-only terminal checks as well as DEBUG_REPORT.md creation. The current “approve only the creation” wording conflicts with reproducing/verifying the problem when a terminal approval is requested. Confirm 8081 has no listener beforehand, add short curl timeouts, and require an actual successful corrected 8080 call in the success rubric.
- A more controlled Exercise 1 prompt is: `/systematic-debugging The workshop server is configured at http://127.0.0.1:8080. A colleague's command calls http://127.0.0.1:8081/health and fails. Run bounded read-only checks against both endpoints, compare their actual results, and create DEBUG_REPORT.md with Symptom, Evidence, Root Cause, Correction, Verification. Do not start or stop processes, change settings, install anything, or search the web. The only permitted write is DEBUG_REPORT.md. Verify the corrected command succeeds.` This proposed replacement has not been run in this review.
- Exercise 2: the skill's SKILL.md searches ~/.hermes/skills although the Windows installation uses LOCALAPPDATA\hermes. Hermes exposes an actual skill directory, so the model may recover; do not make that recovery part of a timed beginner exercise. Supply a tested Windows-aware invocation. Inspection displays a 50-line preview, so it is not a complete audit of the script and network behavior. Explicitly tell attendees to answer the installation confirmation. Classic memes are rendered by Python/Pillow from downloaded templates; Gemma orchestrates/selects/captions them. Avoid suggesting that this setup performs diffusion image generation locally.
- Exercise 3: replace “Work read-only” with “Do not modify the system; the only permitted write is LOCAL_AI_READINESS.md.” Use the actual active Hermes home. Add a short play-around task such as changing report headings or adding a bounded disk check, then restarting and rerunning to observe the skill change. Its present instructions are mostly copy/paste rather than experimentation.
- TASKS.md incorrectly refers to the extracted directory and a server in a separate PowerShell window. The installer copies to USERPROFILE\Hermes-Local-Workshop and starts a hidden background process. Use the installed path consistently.
- Both README documents show a relative stop-script command after changing into hermes-practice. In that state, .\Stop-HermesLocalWorkshop.ps1 is not present. Use an absolute installed path or ..\Stop-HermesLocalWorkshop.ps1 from practice. Make restart a single obvious participant action.
- Correct “50 minutes you Kathy.” The tasks total 47–52 minutes before explanation, navigation, retries or sharing. Either allow 65–75 minutes excluding installation, or make the second meme optional and shorten custom-skill authoring. These are planning recommendations; measured end-to-end timings on the slowest participant laptop should set the final agenda.
- Regenerate both checksum manifests after changing covered files. The current hashes are correct; failing to update them after fixes will intentionally stop installation.

**Workshop acceptance gate**

Before calling the package ready for the event, run the frozen ZIP on at least one fresh standard-user PTL laptop and the lowest-memory target configuration on the event network. Verify first install, actual skill/file output, both readable memes, stop/start after reboot, setup rerun with the server already running, interrupted/corrupt model recovery, port conflict handling, and a profile path containing spaces. Record the driver/SKU/RAM and elapsed installation/task times. Preinstall for attendees at least a day before, require artifact-based readiness confirmation, and have a verified local recovery package plus a paired-work fallback for a laptop that cannot be repaired in-session.
